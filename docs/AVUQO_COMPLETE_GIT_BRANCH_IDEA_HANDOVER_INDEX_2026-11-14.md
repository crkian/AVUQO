## 9. Source and handover intake procedure for every new idea

For each new proposal, first attach its **source ID** (S01–S09 or a new S10+) and requirement/workstream ID (P0–P4 / G01–G12 / UI/DATA/partner ID). Then:
1. Add the exact idea and owner decision to [ROADMAP](./ROADMAP.md) or the relevant specialist spec, with acceptance and dependency. If it conflicts with original owner files, record the conflict.
2. Link the actual implementing file/PR or mark **idea only**, **owner review**, **blocked**, **private tested**, **production-code READY**, or **end-to-end accepted**. Do not fill evidence gaps with optimistic wording.
3. Record provider/source rights, privacy, media provenance, genuine price/stock/all-in fee evidence and role gates.
4. Use one short-lived branch based on current main, one narrow PR, CI/secret checks and preview. Keep the work in its current source files, not a parallel new platform.
5. After merge, verify the exact Vercel READY commit and live route (and Supabase/provider/owner test when relevant). Update [current machine state](./AVUQO_CURRENT_STATE.json), [live handover](./AVUQO_LIVE_HANDOVER.md), [status](./PROJECT_STATUS.md), [changelog](../CHANGELOG.md), and this index if a new idea/branch class appears.
6. Let verified merged-PR branch cleanup remove unneeded refs. Reconcile historical branches by exact source-vs-main proof before deleting. Keep original design/security history until preserved.
