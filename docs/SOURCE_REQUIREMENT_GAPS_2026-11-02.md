## Correctness gaps to preserve
1. **Wishlist and affiliate planning basket:** components/collections/AddToCollectionButton.tsx writes user-held snapshots from the browser to account-scoped lists. Existing RLS secures list ownership; it does not prove that stored title/price/merchant values are revalidated by a trusted server at save time. Public product views have verified-offer gates, but browser-held values can become stale or be modified. The P0-03 acceptance must include tampered/stale snapshots, duplicates, and the labelled mailto output. Do not use saved snapshots as verified public price evidence.
2. **Search coverage:** the search implementation first requests a limited verifiedProductIndex(60), then performs keyword matching on that subset. A real authorised catalogue index, query-intent logic and category-specific filters are still missing.
3. **Mobile:** a Next.js manifest with display=standalone does not prove a native app, push notifications, installation quality, offline functionality or device-store publication. The master specification explicitly allows native work only as commercially justified.
4. **Grocery source integrity:** customer-supplied overrides are not merchant-verified prices, and partial baskets cannot be described as cheapest complete. A complete basket made of user prices is also not a provider-confirmed cheapest basket.
5. **No synthetic completion claim:** 4,588 private Awin feed rows include duplicates and have 0 approved records; 6 offers are demo-only; no licensed grocery prices or conversions were observed. M0–M4 labels should not be converted into a fabricated overall percentage.
6. **Marketing and automation:** a scheduled draft, planned campaign or a disabled Buffer worker is not social publication, revenue or a running provider campaign.
